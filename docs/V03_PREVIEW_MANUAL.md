# V0.3 浏览器演示控制页手工用例

## 范围

本机查看地址：`http://127.0.0.1:4173/preview.html`。服务停止时先执行`npm run build`再执行`npm run preview:browser`；这只是本机地址，不是可供其他设备直接访问的公网地址。无需启动桌宠。

演示入口为 `/preview.html`。它只在普通浏览器中运行，页面内嵌 `/counter.html?preview=1` 与 `/settings.html?preview=1`，用 `postMessage` 传递模拟场景、按键累计和点击累计。演示数据不会写入真实存档，也不会申请输入监控权限；这只是一组展示数据，不跑真实计时或收益算法。

协议消息为：

```ts
{ type: 'dual-pet-preview', scenario: 'normal' | 'away' | 'permission' | 'locked' | 'legacy' | 'capped', keys: number, clicks: number }
```

`keys` 与 `clicks` 均为 0–100000 的累计整数。子页发送 `{ type: 'dual-pet-preview-ready' }` 后，控制页会校验 `event.origin` 和消息来源 iframe，再重发当前消息；iframe `load` 时也会发送一次。

## 手工用例

1. 浏览器打开 `/preview.html`。应看到“模拟数据”标识、6 个场景按钮、按键/点击控制和两个真实页面预览；不会出现 Tauri 权限提示。
2. 选择“正常”。应看到陈工作、江站立，且两人都在场。
3. 依次选择“离场、权限、锁屏、旧存档、上限”。每次切换后两个 iframe 都应更新到相同场景，页面说明文字同步变化；“离场”应仅让江离场，陈仍计入展示数据。
4. 在任意场景增加按键或点击后再切换场景。切换应自动将 `keys/clicks` 清零，避免把锁屏等场景的模拟输入误解为切换回正常后的补算。
5. 点击模拟按键 `+1`、`+10`，再点击模拟点击 `+1`、`+10`。显示的累计数应分别增加，且两个 iframe 收到同一组数值；单场景输入加成示例最多为键盘 +1 / 点击 +1，但展示次数仍可增加。
6. 将两种累计数增加到接近 100000 后继续点击。数值不得超过 100000；不应出现负数、小数或溢出格式。
7. 点击“重置模拟数据”。场景回到“正常”，按键与点击回到 0，两个 iframe 立即收到重置后的消息。
8. 刷新浏览器页面。控制值应回到初始状态，不应从存储中恢复；两个子页加载完成后仍显示初始演示数据。
9. 在控制页外部打开浏览器开发者工具，确认点击控制页按钮不会触发真实键盘/鼠标监听、权限请求或存储写入；这里只允许观察，不要向系统注入输入。
10. 让任一 iframe 刷新或在加载较慢时打开页面。子页 ready/load 后应恢复到当前控制值，而不是停留在旧值。
11. 在 Tauri 窗口中打开 `/preview.html`。页面应停止演示并提示“请用浏览器打开”，不应创建 iframe、发送演示消息或请求权限。

## 验收边界

这是渲染与状态演示，不是窗口验收。桌面窗口位置、透明度、原生键鼠采集、系统权限、锁屏/解锁行为和真实存档仍需在目标环境单独验收。不要用 UI 自动化或 `npm test` 作为本页验收；本轮只执行 `npx tsc --noEmit`，以及明确针对预览纯逻辑的测试（如有）。
