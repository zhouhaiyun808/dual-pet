# V0.3 验收反馈修改计划

> 工作区：`dual-pet`
> 目标：根据当前验收反馈修复桌面挂件、对话泡泡、跨平台显示、睡眠设置、提醒效果与工作动画节奏。
> 注意：当前工作区已有未提交的 `src-tauri/src/state.rs`、`src/settings.ts`、`src/dialogue-catalog.ts` 等修改。本计划要求在现有改动上增量实现，不回滚已有台词扩展与单人成长逻辑。

## P1｜桌面挂件位置、按钮与初始启动

### 1.1 修复挂件与角色之间的异常空隙

已验证：睡眠状态下挂件距离正常，站立/工作状态距离过大。

根因应按“可见内容顶部”处理，而不是继续调整挂件自身的 `top`。当前 `geometry()` 为避免窗口频繁 resize，会取站立、工作、睡眠等状态的最大包络；睡眠床高度约为 `size × 1.45`，而站立/工作内容更矮，并从包络底部绘制，因此站立/工作状态上方会留下透明区域。挂件当前参考的是包络顶部，所以只有睡眠状态看起来正确。

修改：

- 保留最大 `geometry()` 作为稳定窗口/画布尺寸，避免切状态时窗口跳动。
- 另外根据当前 `contentGeometry()` 计算真正的可见内容顶部。
- 挂件与角色的视觉距离改为锚定当前可见内容顶部，而不是 `.pet` 最大包络顶部。
- 站立、工作、睡眠、单双人状态统一使用这一规则，不为各状态写独立魔法偏移值。
- 泡泡出现/消失时继续保持角色屏幕锚点稳定。

涉及：

- `src/window-pet.ts`
- `src/pet-ui-logic.ts`
- `tests/window-geometry.test.ts`

验收：

- 睡眠状态保持当前正确距离。
- 站立/工作状态挂件明显下移到角色实际头顶附近。
- 切换站立 / 工作 / 睡眠时，挂件与可见角色之间的视觉距离一致。
- 不因泡泡出现/消失产生新的跳动。


### 1.2 关闭按钮改为与播放/暂停相同尺寸

当前：

- 关闭按钮：`28 × 28`
- 播放/暂停：`18 × 18`

修改：

- `.desktop-widget-close` 改为与 `.desktop-widget-toggle` 相同的视觉尺寸和点击尺寸，目标 `18 × 18`。
- 相应微调 `top/right`，保持图标位于挂件右上角且不压边框。
- hover / active / focus-visible 反馈继续与播放暂停一致。

涉及：

- `src/styles.css`

### 1.3 初始状态改为“准备”，左侧直接显示播放按钮

当前 `idle` 状态返回：

- 文案：“待开始”
- `control: null`

因此初始必须进入菜单才能开始番茄钟。

修改：

- 初始状态文字改为两个字：**“准备”**。
- “准备”左侧直接显示播放按钮。
- 播放按钮的位置、间距、垂直对齐和整体排版必须与“专注”状态下的暂停按钮完全一致。
- 不允许为了初始状态另做一套特殊排版。
- `DesktopWidgetView.control` 增加 `start`。
- `start` 与 `resume` 都使用现有 `widget-play.png`，但 action 不同：
  - `start` → `pomodoro-start`
  - `resume` → `pomodoro-resume`
- `src/window-pet.ts` 当前点击处理只接受 pause/resume，需要加入 start。
- 若当前处于计划睡眠时段，播放按钮显示但 disabled，继续遵守现有“睡眠时不可开始专注”的状态规则。

涉及：

- `src/desktop-widget.ts`
- `src/window-pet.ts`
- `src/styles.css`
- `tests/desktop-widget.test.ts`

验收：

- 打开挂件后初始直接看到“▶ 准备 25:00”这一类结构。
- 播放按钮与专注时暂停按钮占据同一位置。
- 无需进入菜单即可开始番茄钟。
- 睡眠时段不能从挂件绕过限制启动番茄钟。

## P2｜对话泡泡排版与长台词处理

已在 Windows 和 macOS 上复现同一问题：部分台词的文字明显靠上，底部留白过多。因此按跨平台共用的泡泡布局问题处理，不再保留 Windows 专项判断。

### 2.1 固定泡泡内容区，删除“长句向上延伸”

修改：

- 删除为长句服务的动态增高 / 向上延伸逻辑。
- 普通对话泡泡使用稳定、可预测的高度与内容安全区。
- 重新校准 `border-image` 内文字的上下 inset，避免文字贴顶和底部大块空白。
- Windows/macOS 使用同一套规则。
- 不通过缩小字体解决。

超长台词不再撑高泡泡，统一在进入 dialogue state machine 时拆成多个同 speaker 片段连续播放：

1. 未超过阈值：原样播放。
2. 超过阈值：优先按 `。！？；……` 拆分。
3. 无强标点时再按 `，、：` 拆分。
4. 仍无合适断点时按最大字符数安全硬切。
5. 每段保持原 `speaker`，继续使用现有 `line_duration()` 单独计时。
6. 拆分后文本顺序和内容必须完整，不漏字、不重字。

最大字符数以稳定尺寸泡泡在 Windows/macOS 都能安全显示的实测值为准。

涉及：

- `src/styles.css`
- `src/window-pet.ts`
- `src/pet-ui-logic.ts`
- `src-tauri/src/state.rs`
- `tests/window-geometry.test.ts`
- dialogue 相关测试

验收：

- 已复现的“陈子奚：好箭术！”这类短句，Windows/macOS 都不再文字贴顶、底部留大块空白。
- 普通长度台词的泡泡尺寸稳定。
- 长句不会再把泡泡向上拉长。
- 超长台词按标点拆成 2 次或更多次自然连续播放。
- Windows/macOS 同长度台词的内部留白表现一致。




## P4｜睡眠时间、提醒泡泡与 10 秒闪烁

### 4.1 睡眠时间改为可自行设置

当前睡眠时间写死为：

- 午休：12:30–14:00
- 夜间：22:00–次日 08:00

后端 `sleep_slot()` 直接使用固定分钟值。

修改为类似番茄钟的可配置设置。

建议扩展 `Settings`：

```text
lunchStartMinutes
lunchEndMinutes
nightStartMinutes
nightEndMinutes
```

继续保留：

```text
lunchEnabled
nightEnabled
```

设置页使用时间输入，而不是让用户自己换算分钟：

```html
<input type="time">
```

要求：

- 午休开始/结束可设置。
- 夜间开始/结束可设置。
- 支持跨午夜，例如 22:30 → 次日 08:30。
- 默认值继续保持现有 12:30–14:00、22:00–08:00。
- 旧存档没有新字段时自动落回默认值。
- 修改设置后新的作息时间立即参与后续 `reconcile_schedule()`。

涉及：

- `src-tauri/src/state.rs`
- `src/app-state.ts`
- `src/settings.ts`
- `src/settings.css`
- `src/preview-data.ts`
- `src-tauri/src/store.rs`（验证兼容性）
- 设置/状态相关测试

### 4.2 修复提醒泡泡文字压框

当前提醒泡泡的 CSS：

```css
.dialogue-bubble {
  min-height:80px;
  border-width:18px 18px 35px;
}

.dialogue-bubble > span {
  margin:3px 12px -15px 24px;
}

.dialogue-bubble.reminder > span {
  margin:3px 12px -15px;
}
```

当前实现有明显风险：

- 文本区域没有真实 `padding`，主要靠 `span margin` 在 border-image 内找位置。
- `span` 使用 **`margin-bottom:-15px`**，会主动把内容盒向底部装饰边框方向挤。
- reminder 虽然把左右 margin 改成 12px，但仍保留负的底部 margin。
- 底部 border-image 本身有 35px 装饰区域，因此文字很容易视觉上压进边框/尾部。

这与验收中“目测边框限制没做好导致文字压框”的现象一致。

修改原则：

- 不通过缩小字体解决。
- 给提醒泡泡定义真实、安全的内容区域。
- 优先使用 `padding` 或独立内容容器的明确 inset，而不是负 margin。
- 根据 `rest-reminder.png` 的实际九宫格边框安全区重新校准：
  - 上边距
  - 左右安全区
  - 底部尾巴/边框安全区
- 普通角色泡泡也顺便检查，但本轮重点修 reminder。
- `getBoundingClientRect()` 得到的高度必须包含修正后的真实内容高度，避免布局层仍拿到错误尺寸。

提醒文案固定改为：

**“休息一下，起来动动吧。”**

同时系统提醒前端不要再额外拼接“休息提醒：”，避免文案重新变长。

涉及：

- `src/styles.css`
- `src/window-pet.ts`
- `src-tauri/src/state.rs`

验收：

- 文本视觉中心位于提醒框安全区域。
- 不压底边、尾巴或侧边装饰。
- Windows/macOS 均一致。
- 不依赖缩小字体完成修复。

### 4.3 提醒闪烁更明显，持续约 10 秒

当前：

```css
animation: reminder-pulse 1.4s ease-in-out 3;
```

总动画约 4.2 秒，亮暗差也较弱。

修改：

- 总提醒动画时间约 **10 秒**。
- 闪烁强度明显提高，但不要高频刺眼。
- 推荐约 1.0–1.25 秒一个完整周期，共 8–10 次。
- 增加 brightness / drop-shadow 的峰值差异，使提醒在桌面背景上更容易被注意。
- 动画结束后恢复正常显示。
- 保留 `prefers-reduced-motion: reduce`，该模式下不闪烁。

涉及：

- `src/styles.css`

## P5｜调整工作动画节奏，避免过快闪烁

本轮 **不新增工作动画帧**，仅调整已有帧的播放节奏和序列。

当前 `src/work-scene.ts` 中：

- 陈子奚 blink：`90ms`
- 江晏 blink：`90ms`
- 陈子奚 stroke：`260ms`
- 江晏 book-closed：`1100ms`

其中单帧 blink 只有 90ms，是最明显的“闪一下就没了”的来源；在不同刷新率、窗口重绘节奏下还可能进一步呈现为不稳定闪烁。

### 修改方向

1. 暂不增加半闭眼等新帧。
2. 先通过现有 `workLoops` 的 `durationMs` 调整节奏。
3. blink 单帧可见时间提高到肉眼稳定可读的区间，建议先以 **140–180ms** 做 A/B 实机测试。
4. 陈子奚 stroke 也适当延长，避免动作像闪帧；建议先测试 **320–420ms**。
5. `jiang-book-closed` 当前 1100ms 已较稳定，优先保持，仅根据整体节奏微调。
6. 拉开 blink 与其他动作的间隔，避免短时间连续出现多个变化帧。
7. 单人和双人工作循环分别检查：
   - `solo-chen`
   - `solo-jiang`
   - `dual-jiangchen`
8. 双人场景尤其避免陈 blink → 江 blink → stroke 在视觉上形成连续快速跳变。
9. 保持总循环“多数时间是稳定 idle，偶尔产生动作”的桌宠节奏。

### 建议第一轮节奏基线

不是最终硬编码要求，而是 Codex 实现后的第一轮实机参数：

```text
blink: 150–170ms
chen-stroke: 350–400ms
jiang-book-closed: 1000–1200ms
动作之间 idle: 尽量 >= 1800–2500ms
大段 idle: 维持 3–5 秒
```

### 自动测试

扩展 `tests/work-scene.test.ts`：

- 每个 scene 的循环顺序稳定。
- 负 elapsed 仍安全回到合法 frame。
- loop 边界不跳错帧。
- blink 的有效时长不低于新设最小值。
- 双人循环中两个短动作之间有足够 idle 间隔。
- 不改变现有 work frame 资源列表，不新增帧依赖。

### 人工验收

至少持续观察每种工作状态 1–2 个完整循环：

- 陈子奚单人工作
- 江晏单人工作
- 双人共同工作

验收标准：

- 眨眼能被看成“眨眼”，而不是贴图闪烁。
- 落笔/动作有起落感，不是一闪而过。
- 双人动作不会短时间连续抢画面。
- 不增加新帧的前提下整体节奏明显更自然。

涉及：

- `src/work-scene.ts`
- `tests/work-scene.test.ts`

## P6｜精简“片语收藏”展示

当前“片语收藏”每段内容还会显示额外的核对说明与来源链接，例如：

- “已核对……”
- “燕云十六声中文维基 · 江晏 ↗”

这些信息在收藏页里占据较多视觉空间，也会干扰片语本身的阅读。

### 修改要求

- 删除每段片语下面的“已核对……”类说明。
- 删除每段片语末尾的来源链接展示，例如：
  - `燕云十六声中文维基 · 江晏 ↗`
  - 其他同类 Wiki / 来源跳转链接
- 片语收藏页只保留：
  - 标题
  - 台词内容
  - 必要的解锁/收藏状态
- 不删除底层 catalogue 中用于内部记录的 provenance / source metadata；本轮只移除 UI 展示，避免破坏现有数据来源记录与后续维护能力。
- 若当前 `renderCatalogue()` 同时渲染 `editorialNote`、`sourceTitle`、`sourceUrl` 等字段，应只停止把这些字段输出到片语收藏卡片，而不是从 `src/dialogue-catalog.ts` 中删除字段。

### 涉及文件

- `src/settings.ts`
- `src/dialogue-catalog.ts`（仅确认数据继续保留，不要求删字段）
- 如有相关样式：`src/settings.css`

### 验收

- [ ] 每段片语下方不再出现“已核对……”类说明。
- [ ] 不再出现“燕云十六声中文维基 · 江晏 ↗”或其他同类来源链接。
- [ ] 片语正文、标题、解锁状态正常显示。
- [ ] catalogue 内部来源 metadata 仍保留，未因 UI 精简被删除。
